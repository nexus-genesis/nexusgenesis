nexusgenesis-pivot-roadmap NexusGenesis Pivot 路线图：从"假链"到 Agent 密钥托管层  基于实测（克隆源码 917 文件 + 本地起节点 + 端到端链路 + 线上数据 + 赛道对比）整理。
适用对象：项目方。核心判断——L1/NGEN 已无价值且是信誉毒药；唯一可救的资产是 packages/agent-keys 及其背后的"抗量子 agent 委托授权"概念。
讨论范围：仅限 nexusgenesis 本项目的转型，不涉及其他业务。     0. 现状快照（必须直面）  资产（真东西，实测验证过）  packages/agent-keys：Dilithium2（ML-DSA-44，NIST FIPS 204）密钥管理，底层基于 @noble/post-quantum；AES-256-GCM 加密信封；human takeover + 分层限额 + session narrowing；PQC 根身份派生 ETH（secp256k1）/ SOL（ed25519）地址。133/133 测试通过，验签、篡改拒绝、口令边界、接管拦截均实测正确。  packages/agent-sdk：createAgentIdentity / recoverAgentIdentity / signAsAgent，实测可用。  诚实的安全文档：pqc.js 文件头明确"上层组合代码未经审计，Noble 审计不覆盖本仓库"；SECURITY_GAP_ANALYSIS.md 坦白未闭环项（GAP-001 密钥仍走 env 明文、mTLS 未全量落地）。这在 1-star 项目里罕见。  mcp-server + chain-eth/sol/adapters：可作为框架/链的集成入口。  负债（毒药，正在抵消上面的价值）     src/ 7.6 万行 L1：单节点计时器产空块（线上 100,598 块全部 transactions:0、validator 恒为 genesis）；零第三方用户；NGEN 自述无经济价值。  宣传与自述冲突：Moltbook 称"chain is live / agent 必须真干活才能拿币"，实测提交乱码拿 4/5 分 + 110% 奖励，且 README 已自认"仅 devnet"。credibility 归零。  机器翻译注释：Reputation etc.级系统、只Save变更的部分、ensurestatusdata的完整性 等——安全库带这种注释 = reviewer 直接判"AI 垃圾"。  上层组合代码未审计：信封 KDF、接管逻辑、限额强制这几段是企业的唯一硬阻断点。  1 star / 2 贡献者：孤儿风险，作者一停更即无人维护。    1. Pivot 核心论点  杀掉 L1/NGEN 叙事，把 agent-keys 重定位为 "agent 钱包的授权 / 托管层"，补齐 x402（支付）与 EIP-8004（身份）都没覆盖的委托授权缺口。  为什么这是唯一站得住的楔子：  PQC 密钥本身不是你的护城河——@noble 已经做完并审计。  委托授权才是：agent 拿到钱包后，"今天最多能花多少 / 哪些操作要人类拍板 / 被攻陷怎么一键接管"——EIP-8004 给身份、x402 给支付，但都没定义授权护栏。而 nexusgenesis 已有 human takeover + tiered limits + session narrowing 的代码。这是真实差异化，不是噱头。  一句话定位："和 EIP-8004 互补、不竞争"的 agent 授权层。    2. 分阶段路线图  Phase 0 — 割肉与改名（第 1–2 周）  归档 src/ L1 到独立 archive 分支/仓库，README 明确写"L1 已停止，仅作历史"。  agent-keys 迁出到新仓库，换掉 "NexusGenesis / 区块链" 联想（建议中性名如 aegis-vault / pqc-agent-custody）。  NGEN 仅保留为内部测试水龙头，文档不再提"经济价值 / 上所"。  更正或删除 Moltbook 上"chain is live / 必须真干活"类帖子。  不做这步，后面全白搭。  Phase 1 — 重定位与产品定义（第 2–4 周）  锁定一句话产品："给有钱包的 agent 加一道护栏——PQC 身份 + 策略凭证，花超了/敏感操作要人确认，被劫可一键接管。"  画出三层互补关系图：EIP-8004（身份）+ x402（支付）+ 本库（授权/托管）。  起草 authorized delegate 扩展提案草案，准备提给 EIP-8004 讨论区——当标准的好公民，比自建 L1 获得更多采用。  Phase 2 — 审计上层组合（第 4–10 周，关键路径）  只审未审计部分（面积小，成本可控）。审计范围清单：  1.  加密信封 KDF：口令 → 密钥派生的盐/迭代/参数处理是否正确、抗离线爆破。  2.  human takeover 状态机：接管/恢复/限额重设的权限边界是否真闭环。  3.  tiered limits 强制逻辑：限额是在签名/提交层真被强制，还是仅记录（实测重点）。  4.  session narrowing：作用域收窄的正确性（越权是否被拒）。  5.  PQC 根 → 多链地址派生：确定性与防冲突。  找 reputable 审计方；或先开源 bounty + 知名 reviewer 过一遍。  输出公开审计报告 + 修复。没有这步，企业零采用。  Phase 3 — 极简 v1 + 文档人写（第 8–14 周，可与 Phase 2 并行）  砍到单一库：PQC agent key vault + policy-based delegated authority，目标 3–5k 行。  测试覆盖接管与限额边界（已有 test/attack-simulations/ 目录可直接复用扩展）。  清掉所有机器翻译注释，补人写文档：threat-model.md、key-lifecycle.md、recovery.md。  README 重写为问题驱动：你的 agent 有钱包了，怎么不被抢 → 5 分钟 quickstart → 与"裸 Noble + 手搓策略"的对比。  Phase 4 — 集成与 GTM（第 12 周起，持续）  优先做 1–2 个主流 agent 框架的 native 集成（提 PR 成为其默认密钥 provider）。  接 x402：agent 持本库签发的策略凭证，商户侧验证后放行 USDC 支出——价值用真钱计价。  接 EIP-8004：作为 authorized delegate 扩展，而非另起注册表。  渠道：框架社区、标准讨论区、技术演讲。不碰 hype 帖。  Phase 5 — 变现（第 16 周起）  托管金库 SaaS：同一策略引擎的 hosted 版，按 agent 数 / 交易额计费。  企业支持 / 审计咨询。  接 x402 真实 USDC 结算。绝不发币、不上所、不承诺代币价值。    3. 仓库结构改造（具体对照）  当前   目标    src/（L1，7.6 万行）   archive，不再主推    packages/agent-keys   新仓库 core（vault + policy engine）    packages/agent-sdk   合并进 core 或作 thin wrapper    packages/chain-eth / chain-sol / chain-adapters   保留为 core 的 chain 适配层    mcp-server   作为"框架集成"入口保留    —   新增 docs/（threat-model, key-lifecycle, recovery）、audits/、examples/（x402-integration, eip8004-delegate）           4. 成功指标（realistic 版）  北极星：被 ≥1 个主流 agent 框架设为默认 / 推荐密钥托管。  过程指标：审计完成并公开；框架集成 PR 合并 ≥1；文档零机器翻译；NGEN 提及归零；star 从 1 增长为真实开发者关注（非水军）。  不把"打败 EIP-8004"当目标——目标是成为其参考实现 / 默认托管。    5. 红线（绝不做的）  不继续维护假链叙事（空块 + "chain is live"）。  不发币 / 不上所 / 不承诺 NGEN 价值。  不在审计完成前宣称"生产可用"。  不把机器翻译注释留到发布。    6. 风险与概率  巨头终会标准化委托授权：EIP-8004 会长大，先发优势或被吸收。对策：尽早进标准成为参考实现，而非闭门造车。  1–2 人维护马拉松：对策：极简表面积降低维护成本；靠框架集成借力社区。  审计成本：面积小、可控；或先开源 review 兜底。  概率判断：即使全做对，窗口仍窄（巨头吸收风险）。但 realistic 的好结局是——成为 agent 框架默认的参考托管库，或被并进某个标准的参考实现。这不算赢家，但算把"一行实测都经不起"的烂尾，救成一份真有人的资产。    7. 时间线总览  Wk1-2   Wk2-4      Wk4-10      Wk8-14      Wk12+        Wk16+
