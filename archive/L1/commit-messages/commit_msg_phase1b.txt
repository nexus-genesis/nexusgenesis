feat(block-reward): Phase 1B — distribute via BLOCK_REWARD transactions

Migrates block reward distribution from direct addBalance calls
to per-validator BLOCK_REWARD transactions. Each validator's
share is now a fully auditable tx in txHistory.

CHANGES
- src/node/genesisNode.js
  - New method calculateBlockRewardShares(totalReward, proposerId)
    Returns array of { address, amount, stake, totalStake,
                       sharePercentage, isProposer }
    Mirrors the old state.applyBlockReward logic but as data
    preparation, not state mutation.
  - createNewBlock: now calls calculateBlockRewardShares and
    applies each share as a separate buildBlockReward tx
    via state.applyTransaction
  - Imported buildBlockReward from utils/transactionBuilder.js

LOGIC
- Collect all active validators with locked stake
- If no validators: full 50 NGEN to proposer
- Otherwise: distribute proportional to stake
  (rewardAmount * validatorStake / totalStake)
- Integer division remainder → proposer
- If proposer not in validator set: remainder creates a new share
- If proposer IS a validator: remainder adds to their existing share

BENEFITS
- Every block reward is now a BLOCK_REWARD tx in txHistory
- Per-validator share is auditable (amount, stake, %, isProposer)
- No code change to state.js's low-level balance methods
- Backward compatible: existing 79 Phase 1A tests pass
