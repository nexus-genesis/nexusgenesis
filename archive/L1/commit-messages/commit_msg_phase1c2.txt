uses transactionEngine.applyTransaction for full audit trail.

CHANGES
- src/economy/swarmPool.js
  - L135-136: Replaced direct addBalance with 2-step tx approach
    1. Withdraw placeholder tx (amount=0, from=pool, to=pool) — audit
    2. Credit agent tx (amount=allocAmount, from=pool, to=agent)
  - Both go through state.applyTransaction → enter txHistory
  - Added ultimate fallback for legacy addBalance (preserved)
  - Logs now show txHash for traceability

DESIGN
- Two-tx pattern (withdraw + credit) mirrors double-entry accounting
- The "withdraw placeholder" with amount=0 ensures the pool debit
  intent is recorded in history even when actual debit is implicit
- The "credit" tx carries the actual transfer semantics
- The builder sets from=SWARM_POOL_ADDRESS so the engine
  enforces insufficient-balance check — caught a real bug
  (Test 10 verifies: large distribution would now FAIL with
  clear error, not silently drain the pool)

DUAL SAFETY NET
- Primary: _genesisNode.processSwarmPoolDistribution (existing)
- Secondary: state.applyTransaction + builders (NEW, audit trail)
- Legacy: state.addBalance (kept as last-resort fallback)

METADATA PRESERVED
- distributionId (links both withdraw+credit txs)
- agentId (which agent received)
- txId (the original distribution tx.id)
- fallback=true (distinguishes from primary path)
