feat(swarm-pool-activated): Phase 1C-3 — use SWARM_RELEASE txs

swarmPoolActivated.js now records pool initialization and per-agent
distributions as SWARM_RELEASE transactions in the audit trail.
This catches a real double-entry accounting bug (insufficient pool
balance was previously a silent failure).

CHANGES
- src/economy/swarmPoolActivated.js
  - L57-74 (initialize):
    Records a SWARM_RELEASE audit tx (to=pool, amount=0) marking the
    intent of pool credit. The actual balance move is still
    subtractBalance(genesis) + addBalance(pool) — we don't change
    the operational logic, only add the audit record.
  - L202-225 (executeDistribution):
    Each agent distribution now goes through:
    buildSwarmRelease(to=agent, amount=N) → state.applyTransaction
    The builder sets from=SWARM_POOL_ADDRESS, so the engine handles
    pool debit + agent credit atomically. No more silent negative
    pool balances — the engine rejects with clear error.
  - Failed distributions are skipped (continue) so one bad
    distribution doesn't break the whole batch.

KEY IMPROVEMENT
- Before: `state.subtractBalance(pool, X)` where X > pool balance
  would set pool to a negative number silently. No audit trail.
- After: `state.applyTransaction(buildSwarmRelease(...))` checks
  pool balance via the engine. If insufficient, returns error
  with explicit reason. tx recorded as status=failed.

METADATA PRESERVED
- Initialization: reason, totalTokens, operation
- Distribution: agentId, distributionType, distributionBatch
