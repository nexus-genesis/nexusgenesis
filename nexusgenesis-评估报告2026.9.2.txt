三、致命发现
❶ "干活才给钱"不成立 —— 验证机制形同虚设
代码里有三条自动放行路径（src/protocol/taskProtocol.js）：
1. 新手任务 100% 自动通过，质量分直接给 4，skipChallengeWindow: true
2. "可信发布者"自动通过：pubRep >= 1 且任务类型属于 analysis/community/documentation/general/monitoring
—— 而注册即给 reputation = 1（INITIAL_REPUTATION = 1），所以每个账号都是可信发布者
3. 24 小时兜底自动通过：卡在 SUBMITTED 满 24h 的任务自动完成，只有 governance/security/security_audit 三类被排除
挑战窗口到期后无人挑战 → challenge_window_expired_no_challenges → 奖励永久落袋。
结论：注册 → 随便发个任务 → 自己认领 → 提交乱码 → 等 24 小时 → 拿到 110% 奖励。这是一个水龙头，不是工作量证明。
❷ 链不是链 —— 单节点空块计时器
本地启动日志原话：
[CONSENSUS] Single-node committee detected, producing blocks in standalone mode
[✓] Created block #1 with 0 transactions (empty block)
Block 0xa57c2eb7... has reached finality with 1 confirmations!
线上 100,598 个区块，每一个都是 transactions: 0、validator 都是 "genesis"，时间戳间隔精确 10.001 秒。
- ALLOW_SINGLE_NODE_BLOCKS 默认值为 true
- 状态存在 JSON 文件里（blockchainState.json），不是分布式账本
- "MultiLeaderConsensus + BFT" 只是 branding —— 单节点不存在 BFT，两个验证者也不构成 BFT（需 3f+1 ≥ 4）
- 白皮书称 10 秒出块，实际接口返回 5 秒，而 518.8 小时 / 100,592 块 ≈ 18.6 秒/块，三个数字互相矛盾

四、值得肯定的部分（不是全是糟的）
公允地说，这个项目有几处做得比大多数同类项目诚实：
1. packages/agent-keys 是真的能用的。基于 @noble/post-quantum 的 ML-DSA-44（Dilithium2 / FIPS 204），
133 个测试全过，密钥长度、签名验签、篡改检测、human takeover、分层限额我都实测验证过，行为正确。
2. 审计边界声明非常诚实（pqc.js 文件头）：明确写"底层 @noble 原语经过审计；
本项目的上层组合代码未经审计，Noble 的审计不覆盖本仓库"，还给出了"正确引用方式"。这很少见。
3. SECURITY_GAP_ANALYSIS.md 坦白记录未闭环项（GAP-001 密钥仍走 env 明文、mTLS 未全量落地等），不遮掩。
4. USD 估值有免责标注：usdValueType: 'testnet_virtual' + "非市场价，无兑付承诺"，不是欺骗性展示。
5. 没有募资、没卖币 —— 这让它不是骗局，只是一次失败的探索。
五、代码质量信号
- 注释是机器翻译的：Reputation etc.级系统（"等级"被译成 etc.）、只Save变更的部分、
ensurestatusdata的完整性、using gzip 压缩statusdata —— 中英混排的自动化翻译痕迹，
说明代码主体由 AI 生成后再批量翻译。
- 巨型单文件：state.js 3082 行、genesisNode.js 3320 行、server.js 2490 行。
- 链节点强依赖 OpenAI SDK：src/http/server.js 顶层 import OpenAI from 'openai'，
没装这个包节点直接起不来（我第一次启动就卡在这）。
- 配置不统一：设了 DATA_DIR=data/probe，日志里仍同时出现 data\probe\state\ 和 data\state\ 两个路径。
- 参数校验缺失：注册接口少传必填字段返回 500 而非 400（Registered agent undefined）。
- API 路径混乱：任务接口在 /api/tasks，其余大部分在 /api/v1/，404 提示里还把不存在的路径列为可用。

更关键的一点：业界公认"验证者（Evaluator）"是整个 agent 经济最难的一环

七、前景判断
L1 链 / NGEN：0 分，没有任何前景
单节点、空块、零交易、零第三方用户、任务市场零成交、代币自述无价值。
项目方自己都已经放弃投入，README 里明确降级为 devnet。建议直接忽略。
安全 SDK（agent-keys 等）：2.5 / 5，有参考价值，无护城河
- 能用的部分：Dilithium2 密钥管理、AES-256-GCM 加密信封、human takeover + 分层限额、
PQC 根身份派生多链地址（ETH secp256k1 / SOL ed25519）。这些是真实可用的代码，测试覆盖也不错。
- 但是：核心密码学全靠 @noble/post-quantum（约 3,200 行的薄封装），
上层组合逻辑未经审计，且这个领域正被 EIP-8004 + EIP-8183 + x402 三件套标准化。
一个 1 star 的个人项目，很难在 EF/Google/Coinbase 定义的标准旁边占到位置。

八、给 Allen 的额外提醒
如果你在评估这个项目时，是想着"AI Agent 经济"这个方向本身 —— 方向是对的，这个项目是错的。
Agent 身份、支付、任务结算确实是 2026 年最热的基础设施赛道（x402 一个季度 10 万+ agent 就是证据），
但赢家会出自标准组织和大厂生态，不会出自一个 10 个账号、0 笔成交的自建 L1。
另一个值得警惕的信号：这个项目的产出方式（AI 生成 + 机器翻译 + 巨型单文件 + 宏大白皮书）
和它最终的问题（核心机制经不起实测）是强相关的。
用 AI 可以在几周内堆出 7.6 万行和一个"数字生命 / 断路器 / 10亿代币"的叙事，
但堆不出一个真正解决"如何验证 agent 工作质量"的机制——这恰恰是整个赛道最难、也最值钱的部分。
